# 安全基线

本文档定义 FileBrowser Enterprise `v1.0-beta` 的安全要求。所有入口默认拒绝未明确授权的操作，并遵循最小权限原则。

## Browse / Preview / Download 三权

- `Browse` 控制目录浏览、资源发现和元数据读取。无此权限时，不得通过列表、搜索或旁路接口枚举资源。
- `Preview` 控制缩略图和在线预览。预览必须同时满足 `Browse` 与 `Preview`；需要返回原始文件内容的预览还必须具备 `Download`。
- `Download` 控制原始文件内容的读取、下载和导出。下载必须同时满足 `Browse` 与 `Download`；具备 `Browse` 或 `Preview` 不代表具备 `Download`。
- HTTP API、WebDAV、Share、归档和编辑器等入口必须使用一致的权限语义，不能通过协议或功能切换绕过三权检查。

## Token 权限交集

- Token 的有效权限是用户当前权限与 Token 授予权限的交集，Token 不得扩大用户权限。
- 签发 Token 时必须按用户当前权限裁剪；用户权限被撤销后，已有 Token 必须立即失去对应权限。
- 过期、撤销、签名无效或权限版本不兼容的 Token 必须拒绝访问，并采用失败关闭策略。
- Token 必须设置有效期、支持撤销，并避免出现在 URL、日志、审计明文或其他可能泄露的载体中。

## Share 隔离

- Share 仅能访问创建时绑定的 Source、路径、文件集合和操作范围，不能继承或探测分享者的其他资源。
- Share 的浏览、预览、下载、上传、修改和删除能力必须分别授权；未授权操作默认拒绝。
- Share 入口不得泄露隔离范围外资源是否存在。密码、有效期、下载次数和用户限制等约束必须在每次请求时生效。
- 普通用户、匿名访问和已认证访问均不得借助 Share 绕过用户权限、Token 权限或路径范围检查。

## Agent 禁止管理员权限

- Agent、自动化任务和服务集成不得使用管理员账号，也不得持有 `admin=true` 的 Token。
- Agent 必须使用独立的普通用户身份和最小权限 Token，并限制 Source、路径、操作和有效期。
- 人工管理员不得将管理员会话、Cookie、Token 或密钥交给 Agent；需要高权限的动作必须由受审计的人工流程执行。

## 审计要求（v1.0 上线要求）

- 必须审计登录与认证失败、Token 签发与撤销、权限变更、Share 变更、文件读写与删除、下载、配额和管理操作。
- 每条记录至少包含时间、操作者、认证方式、来源地址、请求标识、动作、目标、有效权限、结果和错误状态。
- 审计日志必须防篡改、限制访问并设置明确的保留周期；时间源必须统一且可追溯。
- 密码、完整 Token、Cookie、密钥和文件敏感内容不得写入审计日志。必要标识仅保留不可逆摘要或受控脱敏值。
- 安全事件必须能够按操作者、Token、Share、资源和时间范围关联检索，并定期验证审计记录的完整性。
