# 产品路线图

本路线图按 2026-10-11 已确认业务排序，不新增版本号或承诺发布日期。现有文档标识与未合并 PR/CI 状态见 [VERSION.md](VERSION.md)，当前能力/证据/待验收矩阵见 [README](../README.md)。源码实现、已开放工具、安装现场与业务验收分别判断。

## 固定目标与职责

FileBrowser 是 AI 与员工共同使用的唯一正式企业文件系统。AI 通过受限文件工具/API 读取实际内容，按公司既定分类及目录规则存入正式文件；员工在同一系统继续查看、编辑、使用。AI 主机仅保存工作副本和中间产物，不以本地缓存代替正式库。

- FileBrowser 核心维护文件 CRUD、授权、持久审计和可恢复部署，不再造 Agent、AI Gateway、OCR 或 RAG。
- Hermes/文件业务工具负责检索、分类、商品匹配和加工；复用官方原生读取/视觉能力。
- Gateway 管理身份、会话、附件引用、任务与投递状态；文件整理逻辑不进入其核心。微信适配负责实际消息/附件收发。

业务基线来自总文档 [PR #9 的 requirements/file-workflows.md](https://github.com/Tangbohu09527/CF_ecommerce-automation-docs/blob/8179533ffade1027d01727cbf5a89a26b491c400/requirements/file-workflows.md)。下列三类业务均已确认，不是可选提案。

## 当前优先：微信真实文件收发

自然语言检索 → 身份/会话授权 → 受控取得原件 → Gateway READY Artifact/Delivery → 微信实际文件/图片及回执。分发已有原件不强制绕行 AI 主机，但必须保留授权和投递边界。回传本机路径或文字摘要不算附件实收。

保留 9 月 26 日只读、9 月 27 日受控文本新建和 10 月 6 日 PDF/PNG 原生读取的分段成功。完整 Agent/微信文字返回按 [FileBridge 入口](../integrations/hermes-filebridge/README.md)所引 Gateway 10 月 7 日记录另判，不能替代实际附件收发验收。当前优先补齐真实文件/图片链路，不按通用 CRUD 顺序优先开发修改/删除。

## 随后：指定资料群分类归档

- 商品图、质检、手卡、授权按实际内容、消息说明及公司目录模板分类，关联商品/规格/批次/版本；未知归属或规则不覆盖时进入待确认。
- 预授权群/发送人、已确定规则、范围内且不覆盖的新增归档应自动执行，不逐文件要求终端审批。现有文本 plan/approve/apply 仅是限定验收入口。
- 保留原件、来源和分类依据；重复消息去重，同名不同内容不得静默覆盖。不得把摘要/附件元数据当作已取得原件。
- AI 离线时 CFserver 收妥原件、持久待处理、恢复后分类是待验收目标；不能承诺当前可补拉所有离线附件。具体群、字典、目录与阈值仍待确认；现有证据不确认其已配置完成。

## 随后：工作副本加工与 API 另存

正式文件 → API 下载至任务 input → work 中加工 → output 检查 → API 新增结果 → 原件关联 → 按需微信分发。默认保留原件，凭证类原始文件与派生结果分开标识。

CLI 下载/新增上传及实际文件读取只是基础，完整 Agent 回存业务尚待验收。另存不等于版本管理；先读哈希再写不等于服务端原子条件写。多写入者、跨 HTTP/WebDAV/分享/编辑器入口的冲突，以及不确定结果/掉电恢复需分项验证，不能从单计划占位测试推导全部安全。
