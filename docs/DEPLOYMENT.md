# 部署基线

可执行的 Debian 生产资产、安装步骤、备份恢复与故障演练位于
[`deploy/README.md`](../deploy/README.md)。本文件保留发布基线；实际部署以该目录中通过验证的固定 digest 资产为准。

本文档定义 FileBrowser Enterprise `v1.0-beta` 的生产部署基线。生产凭据、正式存储路径和环境专用配置必须由部署系统管理，不得提交到仓库。

## Debian

- 使用仍处于安全支持期的 Debian 稳定版，并在上线前安装系统安全更新。
- 使用独立的非登录服务账号运行服务；应用进程和文件目录遵循最小权限原则。
- 将程序、配置、数据库、业务文件和日志分离管理。数据库与业务文件必须位于持久化存储中。
- 仅向反向代理开放应用监听端口；主机防火墙只开放 SSH 管理入口以及 `80/443` 必要流量。
- 使用系统日志或集中日志采集，并统一主机时间同步。

## Docker Compose

- 生产 Compose 文件必须固定内部镜像的 `tag@sha256:digest`，禁止仅使用标签或 `latest`。
- 容器使用非 root 用户运行，并为数据库、配置和业务文件配置明确的持久化挂载。
- 本项目生产配置在容器私网监听非特权端口 `8080`，不发布宿主端口；仅由 Nginx 对外提供 `80/443`。
- 配置 `restart` 策略、资源限制和 `/health` 健康检查；服务就绪前不得接收外部流量。
- 密钥和密码使用部署环境的 Secret 机制注入，不写入镜像、Compose 文件或仓库。

## Nginx

- Nginx 作为唯一公网入口，将请求转发到受控网络内的 FileBrowser Enterprise 实例。
- 正确传递 `Host`、客户端地址和协议相关的转发 Header，并只信任受控代理写入的 Header。
- 根据业务文件上限设置请求体大小、上传超时和代理超时；流式上传下载不得被不合理缓冲或截断。
- 若启用实时功能，必须验证连接升级、长连接超时和并发连接限制。
- 管理接口、健康检查和内部诊断端点不得无条件暴露到公网。

## TLS

- 公网和非可信网络访问必须使用 HTTPS，最低启用 TLS 1.2，优先启用 TLS 1.3。
- 使用受信任证书；自动续期由部署环境提供，本仓库只提供续期后的配置检查、完整 stack reload 和实际呈现证书校验入口。
- HTTP 应重定向到 HTTPS。确认所有子域均支持 HTTPS 后再启用 HSTS。
- 禁用过时协议和弱密码套件，保护证书私钥，并定期验证证书有效期和完整链。

## Backup

- 本仓库本地快照包括应用数据库、部署配置、认证与加密关键材料和业务文件；Docker/集中审计日志由日志平台独立保留，不在该快照内。
- 在停止写入、维护窗口或存储一致性快照中备份数据库与业务文件，确保二者处于可恢复的一致状态。
- 同机本地快照含明文高敏 secret，不是最终灾备；必须经批准的 Restic/Borg 流程加密导出到独立故障域，并按组织要求设置保留周期和访问控制。
- 定期执行恢复演练，校验备份完整性，并记录恢复点目标和恢复时间目标。
- 任何升级前必须生成一次已验证的备份；未验证可恢复性的文件副本不视为有效备份。

## Upgrade

1. 阅读目标版本发布说明，确认数据库、配置、权限和存储格式的兼容性。
2. 在隔离环境使用生产数据脱敏副本演练升级，并验证核心权限、Share、WebDAV、上传、下载和审计流程。
3. 固定目标构建或镜像摘要，完成升级前备份及恢复校验，再进入维护窗口或停止写入。
4. 执行升级后检查 `/health`、日志、数据库迁移状态、版本信息和反向代理连通性。
5. 通过普通用户和最小权限 Token 验证 Browse、Preview、Download、Create、Modify、Delete 与 Share 边界。
6. 发生故障时使用兼容的旧版本和升级前备份回滚；不得对已迁移数据库直接原地降级。
