# FileBrowser 权限修改

## 强制流程

1. 读取根目录 `AGENTS.md`、权限定义、请求上下文、路由处理器和现有权限测试。
2. 运行 `git status --short`，保留所有用户修改，尤其不得修改或覆盖 `backend/http/resource_test.go`。
3. 先编写或运行能够复现目标行为的测试，确认修复前的实际结果。
4. 建立权限矩阵，至少区分：
   - 新建文件与覆盖已有文件。
   - `Create` 与 `Modify`。
   - 普通用户与管理员。
   - 用户权限与 Token 权限。
5. 检查相关 HTTP `PUT` 和 `POST` 流程。
6. 检查 WebDAV、分享上传和编辑器保存入口；涉及下载、删除、复制或移动时检查相应入口。
7. 实施最小修复，不扩大权限、不复制已有判断逻辑、不改无关模块。
8. 先运行权限专项测试，再运行受影响包和入口的回归测试。

## 权限边界

- 不用管理员测试代替普通用户测试。
- 验证 Token 权限不能超过当前用户权限，并覆盖权限撤销后的行为。
- 对不存在的目标验证创建权限；对已存在的目标验证修改权限。
- 验证拒绝路径没有创建、截断或覆盖文件。
- 检查 URL 编码、特殊字符、路径规范化和分享路径是否改变权限判断。
- 不访问生产存储、生产数据库或正式服务。

## 验证与输出

从已有测试名称和包路径派生专项 `go test` 命令，再按范围使用 Makefile 的后端测试或 Lint。不得修改测试来掩盖失败。最终报告专项场景、命令、结果、相关回归、未运行检查、diff 和 Git 状态。
